# 레퍼런스 탐색 (explore-reference)

사용자는 원하는 것을 말로 설명하지 못한다. 대신 보거나 들으면 좋고 싫음을 고를 수 있다.
그래서 넓게 보여 주고, 고른 것으로 좁히고, 다시 넓히기를 반복한다.

## 순서

### 1. 의도를 한 줄로 잡는다

요청을 쉬운 말 한 줄로 적는다 (예: 「카드 게임 결과 화면 — 이긴 사람이 돋보이게」).
이미 있는 기준(메모리의 취향 · 확정 문서 · 사용자가 준 자료)이 있으면 함께 적고, 싫다고 한 것은 처음부터 뺀다.
묻지 않고 시작한다. 의도 한 줄은 1회차와 함께 보여 주고, 틀리면 사용자가 바로잡게 한다.

### 2. 1회차 — 넓게 모은다

인터넷에서 8~12개를 모은다.

* 의도와 가까운 것 절반 + 일부러 방향을 흩어 놓은 것 절반
* 흩어 놓은 것끼리도 방향이 달라야 한다. 무난한 평균끼리 모으지 않는다.
* 검색어를 2~3가지로 바꿔 쓴다 (대상 이름 · 느낌 · 비슷한 장르)
* 검색어에 프로젝트 이름 · 내부 정보를 넣지 않는다

### 3. 한 페이지에 보여 준다

번호를 붙여 한 페이지(아티팩트)에 모은다. 회차마다 같은 페이지를 갱신한다.
항목마다: 번호 · 볼 수 있는 실물 · 출처 링크 · 한 줄 특징.

| 대상 | 실물 |
| --- | --- |
| 화면 · UI · 아트 · 연출 | 캡처 · 영상 링크 (이미지가 안 실리면 링크 + 한 줄 묘사) |
| 소리 | 들을 수 있는 링크 · 플레이어 + 분석 도구로 잰 길이 · 음량 |
| 글 | 짧은 발췌 |

### 4. 고르게 한다

좋음 · 싫음만 번호로 받는다 (「3 7 좋음, 5 싫음」). 이유는 묻지 않는다. 사용자가 이유를 말하면 그대로 적어 둔다.

### 5. 읽은 것을 말하고 다시 탐색한다

* 좋음의 공통점 · 싫음의 공통점을 한 줄씩 말한다. 틀리면 사용자가 바로잡는다.
* 다음 회차는 6~8개: 좋음 주변 4~6개 + 아직 안 가 본 방향 2개
* 싫음의 공통점은 빼고, 이미 보여 준 것은 다시 넣지 않는다

### 6. 멈춘다

* 「이거다」 가 나오거나, 좋음 2개 이상이 같은 방향으로 모이면 끝낸다
* 3회차가 넘으면 지금까지를 정리해 보여 주고 계속할지 묻는다
* 좋음이 하나도 없는 회차가 두 번 이어지면 의도 한 줄이 틀렸을 수 있다 — 의도를 다시 잡자고 제안한다

### 7. 레퍼런스 보드로 정리한다

* 고른 레퍼런스: 출처 · 좋은 점(말로)
* 공통 방향 한 줄 · 피할 것 한 줄
* 드러난 취향(좋다 · 싫다)을 메모리에 남긴다
* make-better 에서 불렸으면 보드를 기준점으로 넘기고 make-better 3 단계로 돌아간다

## 지키는 것

* 레퍼런스는 기준으로만 쓴다. 그대로 베끼거나 받아서 결과물에 넣지 않는다. 가져다 쓰려면 라이선스를 따로 확인한다.
* 모든 항목에 출처를 단다. 출처를 못 찾은 것은 넣지 않는다.
* 소리를 직접 듣지 못하면 분석 도구로 잰 것만 말한다. 들은 척하지 않는다.
* 탐색만 한다. 안을 만들거나 원본을 고치지 않는다.

## 하지 않는 것

* 「어떤 느낌을 원하세요?」 부터 묻기
* 한 회차에 의도와 가까운 것만 모으기
* 사용자 대신 고르고 끝내기
